================================================================================
                            1) نظرة عامة
================================================================================

HAM-FH منصة ألعاب ثنائية بسيطة تعمل عبر الإنترنت بين لاعبين في مكانين
مختلفين (بدون شبكة محلية). كل لعبة مستقلة بملفها، وتتصل بخادم مركزي عبر
WebSocket.

- الخادم    : Python + FastAPI + WebSocket، يعمل على Termux (هاتف).
- الواجهات  : HTML + CSS + JS مدمجين في ملف واحد لكل لعبة. بلا مكتبات خارجية.
- الاتصال   : WebSocket عبر HTTPS/WSS، يُفتح للإنترنت بواسطة cloudflared.
- التوسع    : إضافة لعبة = نسخ مجلد لعبة قديمة وتعديله + سطر في السجلّ.

[3] core/base_room.py
--------------------------------------------------------------------------------
الموقع  : مجلد core.
النوع   : Python.
الدور   : القالب الأم لكل غرفة لعبة على الخادم.

المحتوى :
  - فئة اسمها BaseRoom تحتوي على الواجهة المشتركة لكل الألعاب.
  - إدارة اللاعبين داخل الغرفة: قائمة players تربط الرمز (X/O) ببياناته.
  - حالة الغرفة: waiting | playing | finished، ومن الفائز إن وُجد.
  - دوال مساعدة: pid_symbol (يبحث عن رمز اللاعب من معرّفه)،
    free_symbol (يبحث عن رمز متاح)، has_enough_players.
  - دوال دورة اللعبة: start_new_game، handle_move، state_for.
  - دالة broadcast لإرسال حالة الغرفة لكل اللاعبين المتصلين.

ملاحظات :
  - كل دالة لها سلوك افتراضي فارغ أو بسيط، وتُعاد كتابتها في كل لعبة
    حسب حاجتها.
  - لا يحتوي أي منطق لعبة محددة.
  - لا يُعدَّل عند إضافة لعبة جديدة، إلا إذا أردت إضافة قدرة مشتركة
    بين كل الألعاب.

--------------------------------------------------------------------------------
[4] core/connection.py
--------------------------------------------------------------------------------
الموقع  : مجلد core.
النوع   : Python.
الدور   : عقل الاتصال. المسؤول عن WebSocket وإدارة الغرف.

المحتوى :
  - قاموس rooms يحفظ كل غرفة مفتوحة، مفتاحه (اسم اللعبة + رمز الغرفة).
  - نقطة نهاية WebSocket على المسار /ws/<لعبة>/<رمز الغرفة>.
  - عند اتصال لاعب جديد:
      * يتحقق من وجود اللعبة في السجلّ GAMES.
      * ينشئ الغرفة إذا لم تكن موجودة.
      * يعطي اللاعب رمزه: إما رمزه القديم (إن عاد) أو رمزًا حرًّا.
      * يرفض الاتصال إذا كانت الغرفة ممتلئة.
      * يطرد اتصالًا قديمًا بنفس الرمز (في حالة إعادة الاتصال).
      * يبدأ اللعبة تلقائيًا عندما يكتمل اللاعبان.
      * يبثّ الحالة الحالية لكل المتصلين.
  - استقبال الرسائل من اللاعبين وتوجيهها:
      * type = "move"  → تُمرَّر إلى room.handle_move.
      * type = "reset" → تُعيد بدء اللعبة إذا انتهت سابقًا.
  - عند انقطاع اللاعب:
      * يُزال من الغرفة.
      * إذا خلت الغرفة، تُحذف.
      * إذا بقي لاعب واحد والحالة كانت playing، تعود إلى waiting.

ملاحظات :
  - لا يحتوي أي منطق لعبة.
  - لا يُعدَّل أبدًا عند إضافة لعبة جديدة. يعمل مع كل الألعاب تلقائيًا
    بفضل السجلّ GAMES.

--------------------------------------------------------------------------------
[7] games/xo/room.py
--------------------------------------------------------------------------------
الموقع  : مجلد لعبة XO.
النوع   : Python.
الدور   : قوانين وحالة لعبة XO على الخادم فقط.

المحتوى :
  - فئة XORoom ترث من BaseRoom.
  - اللوحة: قائمة من 9 خانات (None أو X أو O).
  - الدور الحالي: X أو O.
  - free_symbol: يعطي الرمز X للاعب الأول، O للثاني.
  - start_new_game: تصفير اللوحة والدور وحالة الفوز.
  - state_for: بناء الحالة التي تُرسل للمتصفح (اللوحة، الدور، الحالة،
    الفائز، رمز اللاعب نفسه، حالة اتصال اللاعبين).
  - handle_move: التحقق من صحة النقرة:
      * هل الحالة playing؟
      * هل اللاعب هو صاحب الدور؟
      * هل الخانة ضمن النطاق 0..8 وفارغة؟
    ثم تسجيل النقرة، وفحص الفوز، وتبديل الدور، وبثّ الحالة.
  - _check_winner: يفحص 8 خطوط فوز ممكنة (3 صفوف، 3 أعمدة، 2 قطرين)،
    ويُرجع رمز الفائز أو "draw" أو None.

ملاحظات :
  - لا يحتوي أي كود HTML أو عرض.
  - عند نسخ هذا الملف للعبة جديدة: غيّر اسم الفئة، game_name، والمنطق
    الخاص بالقوانين، وأبقِ على الواجهة العامة كما هي.

--------------------------------------------------------------------------------
[8] games/xo/index.html
--------------------------------------------------------------------------------
الموقع  : مجلد لعبة XO.
النوع   : HTML مع CSS و JavaScript مدمجين.
الدور   : واجهة لعبة XO في المتصفح، وهي أيضًا نقطة الاتصال بالخادم.

المحتوى :

  (أ) قسم CSS :
      - متغيرات الألوان في :root (bg, panel, accent, x, o, text, ok...).
      - تنسيق عام للجسم والشاشات.
      - تنسيقات شاشة الاستقبال: العنوان، زر «إنشاء غرفة»، نموذج الانضمام.
      - تنسيقات شاشة اللعب: شريط علوي، مؤشرات اللاعبين، شريط الحالة،
        لوحة 3x3، شكل الخلية، ألوان X و O، تأثير الفوز.

  (ب) قسم HTML :
      - شاشة الاستقبال (id=entry): زر إنشاء غرفة + نموذج إدخال رمز.
      - شاشة اللعب (id=game، مخفية مبدئيًا): شريط الغرفة، زر نسخ الرابط،
        مؤشرات اللاعبين X و O، شريط الحالة، حاوية اللوحة، زر لعبة جديدة.

  (ج) قسم JavaScript :
      - توليد رمز غرفة عشوائي (4 أحرف).
      - معرّف لاعب دائم لكل تبويب (pid) محفوظ في sessionStorage.
      - قراءة رمز الغرفة من رابط الصفحة (?room=XXXX).
      - إذا لم يوجد رمز: عرض شاشة الاستقبال وربط أزرارها.
      - إذا وُجد رمز: عرض شاشة اللعب.
      - بناء لوحة 3x3 ديناميكيًا مع ربط حدث النقر.
      - الاتصال بالخادم عبر WebSocket على /ws/xo/<الرمز>?pid=<pid>.
      - إعادة المحاولة تلقائيًا كل 1.5 ثانية عند انقطاع الاتصال.
      - استقبال رسائل الحالة (type=state) واستدعاء render.
      - render: تحديث اللوحة، مؤشرات الاتصال، مؤشر الدور، شريط الحالة،
        وإبراز خط الفوز إن انتهت اللعبة.
      - زر نسخ الرابط: ينسخ عنوان الصفحة كاملًا ليشاركه اللاعب مع صديقه.

ملاحظات :
  - الملف مستقل تمامًا، ولا يعتمد على أي ملف خارجي.
  - عند نسخ هذا الملف للعبة جديدة: أبقِ قسم الاتصال كما هو، وغيّر
    مسار WebSocket من xo إلى اسم اللعبة الجديدة، وغيّر الواجهة والمنطق
    البصري حسب اللعبة.
  - كل القوانين الفعلية موجودة على الخادم، هذا الملف يعرض ويرسل فقط.

================================================================================
                        4) دورة حياة الرسائل
================================================================================

[المتصفح]                             [الخادم]
    │                                     │
    │  WebSocket handshake                │
    │────────────────────────────────────►│
    │                                     │  إنشاء/إيجاد الغرفة
    │                                     │  تعيين رمز اللاعب
    │◄──────── state (waiting) ───────────│
    │                                     │
    │  (يدخل اللاعب الثاني)               │
    │◄──────── state (playing) ───────────│
    │                                     │
    │  { type: "move", index: 4 }         │
    │────────────────────────────────────►│  تحقق + تحديث + فحص فوز
    │◄──────── state (playing/finished) ──│  (لكل اللاعبين)
    │                                     │
    │  { type: "reset" }                  │
    │────────────────────────────────────►│  لعبة جديدة
    │◄──────── state (playing) ───────────│
    │                                     │
    │  (انقطاع)                           │
    │────────────────────────────────────►│  إزالة اللاعب
    │                                     │  إعادة الحالة إلى waiting
    │                                     │  إبلاغ اللاعب المتبقي



================================================================================
                        5) إضافة لعبة جديدة (خطوات)
================================================================================

1. انسخ المجلد games/xo/ إلى games/<اسم-اللعبة>/.

2. عدّل games/<اسم-اللعبة>/room.py:
     - غيّر اسم الفئة و game_name.
     - اكتب قوانين اللعبة داخل start_new_game و state_for و handle_move.
     - أبقِ على نفس أسماء الدوال العامة لأن core/connection.py يعتمد عليها.

3. عدّل games/<اسم-اللعبة>/index.html:
     - غيّر الواجهة والأنماط حسب اللعبة.
     - في قسم الاتصال، غيّر مسار WebSocket من /ws/xo/ إلى /ws/<اسم-اللعبة>/.

4. افتح games/__init__.py وأضف:
     - سطر استيراد فئة الغرفة الجديدة.
     - سطرًا في قاموس GAMES:  "<اسم-اللعبة>": <اسم-الفئة>.

5. افتح static/index.html وأضف زر رابط جديد:
     <a class="game" href="/games/<اسم-اللعبة>/">...</a>

6. أعد تشغيل الخادم. لا حاجة لأي تعديل في core/ أو server.py.



================================================================================
                        6) التشغيل على Termux
================================================================================

التهيئة (مرة واحدة) :
    pkg update && pkg upgrade -y
    pkg install python -y
    termux-wake-lock
    pip install fastapi uvicorn websockets

إنشاء المجلدات :
    mkdir -p ~/HAM-FH/{core,games/xo,static}
    cd ~/HAM-FH

التشغيل :
    uvicorn server:app --host 0.0.0.0 --port 8000

الفتح للإنترنت (اختياري، للعب مع صديق خارج الشبكة) :
    pkg install cloudflared -y
    cloudflared tunnel --url http://localhost:8000
    ثم استخدم الرابط العام الذي يظهر.



================================================================================
                        7) قواعد ذهبية
================================================================================

- core/ لا يُعدَّل عند إضافة لعبة. إذا احتجت تعديله، فالسبب مشترك بين كل
  الألعاب، ولا يجب أن يكون خاصًّا بلعبة واحدة.

- server.py لا يحتوي منطق لعبة.

- كل لعبة في مجلدها، وكل شيء تحتاجه داخله.

- كل قوانين اللعبة على الخادم. الواجهة تعرض وترسل فقط.

- ملف HTML لكل لعبة مستقل تمامًا، بلا استيرادات خارجية.

- إضافة لعبة = مجلد جديد + سطر في games/__init__.py + رابط في static.

- WebSocket هو قناة الاتصال الوحيدة بين المتصفح والخادم.
